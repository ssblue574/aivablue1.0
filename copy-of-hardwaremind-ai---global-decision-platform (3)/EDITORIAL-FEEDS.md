# Aiva home editorial feeds

The homepage and factual news detail routes only use the curated feed after 00:00 Beijing on November 28, 2026. Legacy source in `data/news.ts` is retained for history and is not imported by either public section or the detail route. No entries are created for a slow news day. Verified onboarding entries in the build expire exactly like the live data. If the network is unavailable, previously loaded data cannot outlive its own time window.

## One-time accepted change

This change is a reviewed pull request to main, not a direct push. Confirm Netlify builds the current nested app; both `public/_redirects` and `public/sw.js` must be present in its publish output. The exact same-origin GET `/editorial-runtime.json` proxies to the repository's public JSON at `https://raw.githubusercontent.com/ssblue574/aivablue1.0/editorial-feed/editorial-feed.json` before the SPA fallback. No private data should live on that branch or in the payload. Browser credentials are omitted, redirects rejected, JSON or text/plain responses are parsed strictly and bounded. Do not substitute an arbitrary remote URL. The root update workflow must keep main manual; no hosting credential or extra backend required.

After approved deployment, verify HTTP 200 and actual JSON (not SPA HTML) on the production /editorial-runtime.json, compare title and body to the pinned editorial-feed commit, verify the main homepage, deep-link reload, both column fresher/expired behavior and no legacy mock labels on desktop and mobile. Netlify's edge proxy, raw GitHub caching, geographic availability and end-to-end production deployment cannot be certified by localhost tests. Same-origin browser routing does not establish China reachability. Stop and report if the endpoint is not readable; bundled stories must never be counted as proof of a current live feed generation.

## Daily workflow

Only update the root-level file `editorial-feed.json` on the dedicated `editorial-feed` branch. Keep both lines' still-fresh items, merge new items against the current blob SHA (compare and swap), validate, then confirm resulting JSON and homepage. Do not commit unrelated files, change production branch, force push, or resubmit approval for daily editorial content when the integration is live. Keep the unique event ID and original source stable, not an updated/aggregated posting date. The version 1 structure matches the example in `public/editorial-feed.json`.

For exact source times, include actual local offset. If only a dated primary disclosure has a known local source date, use its earliest defensible local timestamp (midnight) to age out conservatively, label `datePrecision: day` and display date only. Do not substitute old news refreshed by a reprint. A new material disclosure or real milestone may be reported once with its own time. Future/expired/malformed items and disallowed sources do not display. Frontiers max 72 hours, startups max 168 hours (both inclusive at exact limit). Verify facts, use original links and original bilingual copy, at least two substantial body paragraphs and a separate attributed Aiva insight. The image is an Aiva-branded non-photographic fallback. Add no unlicensed images. Comments and likes not connected; no fake counters. No changes to product approval.
